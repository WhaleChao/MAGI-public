# MAGI 操作手冊

> 版本：2026-07-02 一般使用者版
> 適用對象：一般使用者、受邀同仁、管理員
> 使用方式：一般使用者用白話中文；管理員可用 `magi` CLI 維運
> 全文採台灣用語

MAGI 可以透過 LINE、Telegram、Discord、網頁與管理員 CLI 使用。日常工作不需要記命令列；你可以像交代助理一樣用白話說。`magi` CLI 是管理員用來啟動、巡檢、測試與發布的工具。

本手冊不放真實案件、個資、帳號、token、portal 截圖或私有路徑。以下範例都使用泛用佔位文字。

## 1. 怎麼使用 MAGI

### 1.1 LINE

- 向管理員取得 LINE 官方帳號或加入方式。
- 直接傳訊息即可，不需要 `/` 前綴。
- 可傳文字、圖片、PDF、語音檔。

### 1.2 Telegram

- 向管理員取得 Telegram bot 或群組連結。
- 第一次使用通常先傳 `/start`。
- 群組可由管理員設定通知主題。

### 1.3 Discord

- 向管理員取得邀請連結。
- Discord 適合電腦前處理附件、看通知、追蹤法扶、閱卷、筆錄、系統健康。
- 管理員可把不同工作分流到不同頻道。

### 1.4 網頁

- 管理員會提供 MAGI 本機或內網網址。
- 第一次使用優先開 `/start` 或 `/dashboard/beginner`，先看新手儀表板。
- 常用頁面包含案件、待辦、法扶、閱卷、檔案與 NERV 狀態頁；NERV 主要給管理員看服務健康。

## 3. 附件處理

### 3.1 支援格式

| 類型 | 常見格式 |
|---|---|
| 文件 | PDF、Word、Excel、PowerPoint、文字檔、Markdown、HTML |
| 圖片 | PNG、JPG、HEIC、WebP |
| 音訊 | MP3、M4A、WAV、FLAC |

### 3.2 上傳後常用指令

1. `翻譯`
2. `摘要`
3. `辨識` 或 `OCR`
4. `歸檔`
5. `轉文字`

MAGI 會盡量保留原文件的標題、段落、表格與引用。掃描件會先 OCR，再處理內容。

### 3.3 自動命名與歸檔

上傳法院文件、判決、通知或書狀時，MAGI 會嘗試辨識法院、案號、文件類型、日期與期限，並產生較一致的檔名。若辨識不確定，會要求人工確認，不會硬猜。

## 4. 法扶

MAGI 可協助管理法扶案件的開辦、進度、補件、結案與提醒。

### 4.1 常用說法

| 指令 | 用途 |
|---|---|
| `<當事人> 已開辦` / `<案號> 已開辦` | 標記開辦 |
| `<當事人> 已報結` / `<案號> 已報結` | 標記結案 |
| `法扶監控` | 查看目前狀態 |
| `法扶回報指令` | 查看可用格式 |

### 4.2 二階段確認

法扶 portal 送出前會走二階段確認：

1. MAGI 先把資料填好，但不正式送出。
2. 系統提供畫面摘要與確認碼。
3. 使用者確認無誤後回覆確認碼，才正式送出。
4. 若不送出，回覆取消指令。

這個設計是為了避免誤送，不要要求管理員關掉。

### 4.3 法扶計數

MAGI 會整理開庭、會議、律見、閱卷、電話聯繫等活動。若同名或資料不足，MAGI 會跳過或要求補資訊，不會只靠姓名硬判斷。

## 5. 閱卷與筆錄

### 5.1 閱卷

```text
閱卷查核 <法院> <案號>
閱卷聲請 <法院> <案號> <當事人>
下載閱卷 <法院> <案號>
```

閱卷聲請、繳費憑證上傳與其他 portal 動作都會保留人工確認，不會主動送出。

### 5.2 筆錄

| 指令 | 用途 |
|---|---|
| `下載筆錄 <案號>` | 查詢或下載單案筆錄 |
| `同步筆錄` | 管理員或排程批次同步 |
| `筆錄更名` | 重新命名已下載文件 |
| `筆錄向量化` | 放入知識庫 |

如果外部網站、驗證碼或帳號狀態異常，MAGI 會通知管理員。

## 9. 系統狀態與管理員 CLI

一般使用者可說：

```text
MAGI 系統狀態
系統健康
今日報告
```

管理員可用 CLI：

```bash
magi status
magi start
magi stop
magi restart
magi menubar
magi zombie
```

NERV 狀態頁可查看資料庫、模型、OCR、NAS / storage、排程與背景服務。若 NERV 紅燈，先不要做批次下載、批次搬檔、DB 還原或正式 portal 送出。

一般使用者日常入口是 `/start` 或 `/dashboard/beginner`；管理員排查服務時才需要進 NERV。

## 10. 管理員發布摘要

發布、部署與交接細節請看 [OPERATOR_RUNBOOK.md](/Users/ai/Desktop/MAGI_v2/docs/OPERATOR_RUNBOOK.md)。

2026-06-23 後的 gate 名稱：

| Gate | 用途 |
|---|---|
| `ci` | 快速公開安全與單元測試 |
| `smoke62` | 本機完整冒煙測試 |
| `production-live` | 私有正式環境 live 驗證 |
| `commercial-release` | 對外分享、銷售、打包前驗證 |

管理員發布入口：

```bash
./venv/bin/python scripts/ops/run_test_suite.py --suite ci
./venv/bin/python scripts/ops/run_test_suite.py --suite smoke62
./venv/bin/python scripts/ops/run_test_suite.py --suite production-live --json-out .runtime/production_live_latest.json
./venv/bin/python scripts/ops/run_test_suite.py --suite commercial-release --json-out .runtime/commercial_release_latest.json
```

重要原則：

- public install、private production、developer checkout 要分清楚。
- 對外發布必須通過 public isolation strict。
- private production 必看 NERV，並保留 DB restore confirmation gate。
- LAF、閱卷、筆錄與 DB restore 不應取消人工確認。
- 業務三模組 live check 使用 `scripts/ops/business_module_live_check.py`，並已納入 `production-live`。

## 11. 隱私與資料安全

- 真實案件、當事人、帳號、token、OAuth 憑證、portal 截圖、DB dump、NAS 私有路徑不得放進 git 或手冊。
- `@heavy` 會使用較強外部模型時，應先做個資遮蔽；不適合送外部模型的內容請使用本機處理。
- 外部 portal 的正式送出必須由使用者確認。
- 批次刪除、批次搬檔、DB restore、migration rollback 都需要管理員確認。

---

## 12. 故障時怎麼辦

| 狀況 | 處理 |
|---|---|
| MAGI 沒回應 | 先等幾秒，再說 `MAGI 系統狀態` |
| 附件沒處理 | 確認檔案已上傳完成，再補一句 `摘要` 或 `翻譯` |
| 閱卷或法扶 portal 失敗 | 等系統重試；連續失敗會通知管理員 |
| 行事曆或統計怪怪的 | 補案號、法院、案由或 OSC 編號讓系統消歧 |
| 網頁錯誤 | 記下時間與頁面，交給管理員看 NERV 與 log |
| NERV 紅燈 | 暫停批次與正式送出，請管理員處理 |

## 13. 使用習慣建議

1. 用白話說，不必背完整格式。
2. 附件先傳，再說要摘要、翻譯、辨識或歸檔。
3. 涉及正式送出、法律判斷、金額、期限時，務必人工確認。
4. 同名或多案情境，主動補案號、法院或案由。
5. 想讓 MAGI 記住偏好，用 `記住：...`；想查回來，用 `回想 ...`。

## 14. 一句話版

MAGI 是可用白話交代工作的法務助理系統；一般使用者負責確認內容，管理員用 `magi` 與 runbook 維持服務、測試、發布與資料安全。
