# 筆錄法官指示待辦抽取器

日期：2026-05-19

## 目標

讓 MAGI 能依照法院筆錄中的法官指示、下次庭期、期限命令與「候核辦」記載，自動建立 OSC 待辦事項，並交由既有 Google 日曆同步流程推送。

## 已掃描的規則來源

- 筆錄索引：`.agent/transcript_index.json`
- 索引量：837 筆，其中目前可讀取約 548 筆
- 主要筆錄資料夾：`05_筆錄`、`06_筆錄`、`08_筆錄`
- 抽樣結果：筆錄尾頁多數可從「法官／審判長諭知」段落抓出待辦，但全文硬抓會誤判權利告知、身分資料、前案日期與例行問答。

## 建立規則

### 高信心，直接寫入

1. 明確下次庭期
   例：「定於115年1月14日上午10時行準備程序」
   寫入：準備程序、言詞辯論、審理、調解、宣判等。

2. 明確期限命令
   例：「7日內補正」、「10日內陳報」、「5日內表示意見」
   寫入：以筆錄日期加期限日數計算，遇假日順延。

3. 候核辦
   例：「本件準備程序終結，候核辦。」
   語意：沒有下次庭期，但仍需追蹤。
   寫入：筆錄日期加 7 日，類型為「追蹤」。

4. 下次庭期前準備
   例：「請兩造於下次準備程序期日前提出證據能力意見及爭點整理。」
   若同份筆錄已辨識下次庭期，寫入庭期前 7 個工作日。

5. 開庭時／到庭時待辦但未指定期限
   例：「請被告開庭時攜帶存摺及交易明細到庭說明。」
   若同份筆錄已辨識下次庭期，寫入庭期前 7 個工作日。

### 待審，不直接寫入

- 有指示但無日期、無期限、無可推導庭期。
- 例：「請被告陳報學經歷。」

### 排除

- 權利告知、緘默權告知。
- 出生、年籍、身分證、住居所。
- 法官例行問答：「有何意見」、「有無其他主張」、「有無其他證據」。
- 無具體作為或期限的程序描述。

## 保護機制

- `apply` 預設不寫入已逾期項目，避免舊筆錄回灌日曆。
- 每筆來源使用「筆錄檔名 + 頁碼 + 規則指紋」，避免同一份筆錄多筆待辦互相覆蓋。
- 同案同類型同日期同時間會去重。
- 中信心只保留在報告中，後續可接入 UI 的「筆錄待辦候選」。

## 指令

```bash
python3 skills/transcript-todo-extractor/action.py --task dry_run --limit 30
python3 skills/transcript-todo-extractor/action.py --task apply --limit 120
python3 skills/transcript-todo-extractor/action.py --task apply --path "/path/to/筆錄.pdf"
```

## 排程

新安裝種子排程：

筆錄待辦已併入 `job_osc_events_refresh`，和 OSC/PDF 建立待辦、Google 日曆匯入/推送同一輪處理。

- 每 6 小時執行
- PDF 待辦、筆錄待辦、Google 日曆匯入/推送同一輪完成
- 高信心直接寫入，過期項目不寫入

本機不再另設獨立筆錄待辦排程，避免兩個時間點互相錯開。

## 驗證

- 單元測試：
  - 候核辦加 7 日
  - 明確庭期
  - 7 日內補正
  - 下次庭期前 7 個工作日
  - 開庭時待辦但未指定期限時，以庭期前 7 個工作日提醒
  - 權利告知排除
- 真實 dry-run：
  - 20 份筆錄，高信心 3 筆、待審 1 筆、錯誤 0 筆
- 真實 apply：
  - 20 份筆錄，高信心 3 筆均為過期項目
  - 寫入 0，過期跳過 3
  - DB 寫入流程啟動正常
